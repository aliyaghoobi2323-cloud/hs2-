(2) Gap fix: HS2_MCONN_STRIPE_RES_GUARD (engine/mconn_stripe_resguard.go)
Cause (arm L/ONL logs): the FAST_RESERVE set-aside links WERE built, but the crowd's light subs took them:
  "pressed" ranks before path in pickKey; during a crowd's arrival every ordinary link is pressed by recent picks,
  so the untouched set-aside link won (on-stripe=234 per 5 s); a set-aside link with a user no longer counts,
  so the fast download's pick found "none (free=98 empty=0)" and waited ~2.5 s for the pool.
Fix: a stripe-held link (set aside or carrying a stripe sub) ranks pressed for light picks (pickLocked and the
  mconn plane key), and is skipped under the refill hold's cap; still taken when it is the only link. Bounded:
  only the reserve (3) + stripe links; never takes a light user's link. No wire change. Default OFF.
Proof (STRIPE_LOG): GL0 "download stripe at 1.401s" -> "stripe pick: link 80 set-aside=true" in the same ms;
  ONL0 at 1.401s -> "stripe pick: none" x4, first sub later.

  echo +1.4 (.91), ping +11.8 (.34): none significantly worse.
