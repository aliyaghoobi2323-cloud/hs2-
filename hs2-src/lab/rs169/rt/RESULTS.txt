Findings
1. RETRY fires a lot now (25-57 per run, vs 0 in the earlier rs169 A/B): retrysilent = joins whose answer path died.
2. NONE of the rs169 paths were exercised: rescue169 repeat/repeatsw/stale/lateans/dupans/laterr/noring/overread = 0 in
   all 4 runs (only "held" > 0 on the I exit: answers saved, never asked for again). Why:
   - every RETRIED raw RESCUE was a FRESH one (er94 role 4, ri=0, trace fresh=true: the conn was opened by the
     rescue join); the non-fresh raw rescues the exit served ("exit RESCUE read" 12-79/run) were never retried;
   - records rescues (RREC) retried on a new join are answered again by the exit in BOTH arms (pre-rs169 behaviour),
     and no late answer arrived on a replaced join (laterr 0: in "ret" mode the first answer is lost for good).
3. GAP in H1 (both arms identical): a retried FRESH RESCUE is refused by the exit -> the conn is reset
   ("exit RESCUE(Bi,0) refused", 3-11 per run; on Iran "join died before ACK ... ended waiting for the ACK").
   Trace example (r1I conn 27b57368d5190d94): iran RESCUE(1,0) fresh=true -> exit "served fresh RESCUE(1,0)" (answer
   lost on the dark return path) -> iran "rescue join silent: retry" -> retry join on 10.60.5.1 -> exit
   "RESCUE(1,0) refused". Cause: onRescue's er94 fresh branch (mconn_rescue.go ~698) sets rscPhase=2/rscSub but never
   calls rescueServedLocked, so the rs169 repeat check (rscSrv.set) fails and the request falls to the refusal.
   Likely fix: in the fresh branch, under rs169Fix, record the answer (rescueServedLocked(bi, 0, sendOff, 0,
   mRecRescueAck, nil)) so a repeat on a newer join is re-answered (rescueRepeatLocked resends records from that
   sendOff); needs a unit test (fresh RESCUE, ACK lost, retry on a newer join) and a check that Iran's [0,Bi) resend
   with the retry is not delivered twice.
Verdict: IDEM=1 is safe under heavy retry (CORRUPT 0 over 4 x 30 byte-checked calls = 14 call-hours, 0
   panics, RSS within noise, retryfail 0). Fewer call deaths (31 vs 45) and crowd fails (6087 vs 7001) with IDEM=1,
