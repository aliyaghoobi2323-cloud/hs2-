(2b) The bh93 S1 outlier (r3bLS1, crowd fail 1291): explained, not a silent-key fault. fail_t per second shows that
almost all crowd failures in BOTH arms are one spike at event+9..10 s (the probe's 10 s request deadline on the
connections that were on the blackholed path when it went dark) plus a second wave at +20..21 s (connections that
redialed onto it before it was cut). Neither a 7 s IP cut nor a 12 s path cut can save requests already in flight
on the dead path. The size of the spike = how many crowd connections sat on the event path at the event: r3bLS1 had
the IP fully in service (no pre-cut, unlike 4 of the other 5 S1 bL runs) and lost 5/10 paths within 12 s (IP cut +
collateral loss cuts 50.2>54.1 3.4 % and 50.2>50.1 3.7 % + the lossy pair). Same pattern in e3bBS1 (477: spike 99 at
+10 s, then 122+126 at +20/21 s). Run-level crowd fail is dominated by this, hence per-event counting.

(3) NOT CLEAN — RE-ADMISSION OF A STILL-BLACKHOLED PATH (new finding; default NOT flipped):
"lb auto2: path X acks again after N silent readings (raw loss 0.0%)" fires on the DIALING side while the path is
still 100 % blackholed (the iptables rule never comes off in these runs), the smoothing restarts from that 0 %
reading and the path is "recovering" ~25 s after the cut. Seen in kh logs of e3bPS1, e4bIS1, e5bPS1, e6bPS1 (bin93
+key) and all 4 mixed runs below (bin95 with the key as an envdef default). "held 16/16" above is only to the end of
a 65 s run (event+35 s); runs N95/X79/X58 show recovering at about event+32 s => held=miss. bh93's 12/12 held had
only 22 s after the event. Likely cause (not proven, out of time): after the cut drains the path, its links have
nothing of their own waiting (no backoff, nothing resent) so the reading is not "silent"; the kharej's segments
out are then its ACKs/dup-ACKs for what the Iran side (re)sends, never retransmitted => raw loss 0 %. Next: treat
a reading with acked == 0 (or no bytes acked since the silence began) as "still silent", not "acks again";
require bytes acked > 0 before silentFold restarts the smoothing; then re-run bI/bP with T >= 120 s.
