== ROOT CAUSE (per-rescue trace, B94_1..3, binary hs2T = base + smux write cut + trace)
  Every started rescue had Ri = 0 and Bi <= 206 bytes (278/278 in B94_1): they are crowd conns OPENED INTO
  the path as it blackholed. Their role-3 first sub (stream open + first request) never reached the exit,
  so the exit had no conn for the id: the RESCUE join waited mconnJoinWait (5 s) in serveMConnSub and was
  dropped as "join missed" (exit joinmissed 290 / 290 / 266 vs Iran started 278 / 278 / 267). The counter

  Iran: lostjoin = endwait = started - acked (the join got EOF after 5.1 s, the conn ended).
  Not the cause (checked by the trace): id mismatch, wrong state machine, accept backlog, rate limiter
  (limited 0), join on the silent path (samepath 0, silentjoin 0), exit conn ended (joinended 0).

== Fixes (commits 4124eaec, b9740352 + this file)
  1. mconnRoleRescueJoin (role 4): when Iran has read nothing and its ring holds every byte from 0, the
     rescue join goes as role 4. The exit attaches it to a known id (plain RESCUE), otherwise opens the
     conn on it in records mode (rscFresh, dials the target), answers ACK(sendOff, 0), Iran resends [0, Bi).
     If the lost first sub arrives later, tbl.create refuses it (closed). TestRescueFreshFirstSubLost.
  2. Sweeper freed the ring of a conn waiting for its ACK (rawW is off after the switch): B95 (role 4 only)
     had Iran "nocover" 32 / 11 / 49 per run. Sweeper now keeps the ring while rscCut is set (atomic;
     the ACK/NAK handlers and the end hook free it). TestRescueSweepKeepsRingUntilAck.
  3. smux: SetWriteDeadline into the past now wakes a Write already waiting (window wait, shaper, dead
     socket). Upstream reads the deadline once per Write, so cutRaw (both sides) could block forever on
     wmu behind a raw write stuck on a dead link. TestWriteCutWakesBlockedWrite fails on the base smux,
     passes now. Only rescue sets a past write deadline (others set now+N), so nothing else changes.
     Cost: one uncontended mutex per Stream.Write.
  4. NAK (0x0f): the exit's ring no longer holds [Ri, Bk): it answers NAK(Bk, Rk) instead of ending the conn;
     Iran resends [Rk, Bi) and puts its raw reader back on the first sub up to Bk (a Read waiting on
     reassembly goes back to raw; switchRead closes the abandoned sub). On a truly dead first sub the conn
     then waits for that sub to die (link close / smux keepalive) instead of ending at once — same end
     result, later. TestRescueNakKeepsConn (TCP loopback first sub, 4 KB ring, 60 KB in flight).
     Lab: nak 0 in every run (the gap case did not occur once role 4 + sweeper were fixed).
  5. Counters for every drop (rescue log line): joinended, joinmissed, lostjoin, refused, cutslow, endwait,
     fresh, freshnew, nak, nakd. HS2_MCONN_RESCUE_TRACE=1: one line per step per rescue (cap 4000).
  6. TestRescueVsUpgradeRace -race flake (1/20): NOT a rescue bug. The failing round had no rescue: plain
     upgrade, raw1 died "read pipe: i/o timeout" right after "reader switched at 0" = the stale read
     deadline that HS2_MCONN_DEADLINE_FIX fixes (on in production via envdef, off in the test binary).
     The test now sets it; -race -count=60 (x20 rounds) clean (was 2 fails in 30).
  7. dgpool.go:604 DATA RACE (pre-existing on ccc988ac/176b3e1f): TestDgPoolRoundTrip passed t.Logf to the
     pools, whose read loop logged after the test returned. tLogUntilDone (mutex + Cleanup).
  Compat: role 4 is only sent on conns opened with role 3 (exit announced capExtMConnRescue = lab er91+
  builds). An er91/er92 exit with the key on would close a role-4 join (= old outcome). rel58/rel59 never
  see role 3/4 (M96 below).
