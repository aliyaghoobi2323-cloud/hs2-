## root cause work (a) — quiet download cost
hs121 logs (k121, key on): Iran (the download receiver) used the KEEPSTALL hole rooms in quiet runs:
  gap_room 304 / 619 / 3076 chunks in qd1on1 (586 Mbit/s) / qd8on1 (1052) / qd8on2 (831); 0 in the faster qd1on2/3
  (859 / 1081). The rooms were checked BEFORE the STRIPE_UP reorder growth (growOOOLocked), so a quiet hole >= 500 ms
  took the +32 MiB room instead of growing oooMax — the reorder bound stayed small for the rest of the run.
  FIX 1: hole rooms (gapRoom / gapFill / holeSub) only after the normal growth fails -> key on == key off until the
  reorder growth is exhausted. hs123: gap_room = 0 in every quiet run (only dark runs: xd1 9333).
Sender (exit) bookkeeping: every write scanned every sub's smux marks (type switch + atomics) and updated the global
  kept counter per chunk (shared cache line, also with the key off since hs112).
  FIX 2: a write trims only its own sub's acked prefix; the all-sub trim runs on the 100 ms tick or when a bound is
  crossed; kept counter updated once per write / drop.
Memory: kept bytes key on 22-32 MB per process (kh) vs the key-off rule (16 MiB per connection, 2 s) — the key keeps
  less on d8 (RSS kh 816/875 on vs 910/911 off) and ~+60..90 MB on d1 (720-752 vs 662-667). No copies: kept chunks are
  references until the smux ack.
What remains: d8 throughput tracks the EXIT scavenger gate width (stripe gate w avg 1.7 of 4.6 live in the 702 run vs
  3.5-4.5 in the 1000-1230 runs, key off runs included) — the gate cuts on path-queue samples; the key does not touch
  the gate or the path-queue measure. Key exit-only 1134/890, Iran-only 1208/1198 (no side carries a cost).

for 57 s, unacked=1) is no longer a candidate. TestAckStallIdleSubNotCandidate. hs123: 0 quiet ack-stall closes in
