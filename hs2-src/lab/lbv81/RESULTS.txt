FINDINGS (fixes behind keys, default off = production unchanged; tests in engine/)
 F1 HS2_LB_DEAD_HYST=P   a steady 0.8 % path sits at the lb2Dead ratio and flips lower/ok (lab2: 30+
    transitions in s1-lab2/an81.txt "h:" line). Band: a lowered path returns to ok only at lb2Dead+P/100.
    Test TestDeadHystStopsFlipping: 27 flips/10 min off, 0 with P=8.  Not A/B'd.
 F2 HS2_LB_SELFQ=K       our own heavy download starts on ONE path (ss: c 338-424 MB/5 s vs 11 MB on the
    others, s1-lab2/ssq-heavystart.txt), BBR fills that path's queue: busy-link rtt-minrtt 37-45 ms for
    ~10 s, judge reads queue 36-42 ms and lowers the clean path to ~0.5 for 20 s (lab2 t=547 c, 912 a; lab3 t=312 b, 437 a, 552 a;
    each a heavy-download start that landed on one path). K: a path carrying > K x the median
    path's acked bytes (and 8 MiB) may not raise its smoothed queue. Test TestSelfQueueNotPunished.
    Speedtest-ping link: light p99 during the first 15 s of each download is +12-16 ms (s1, --all) and
    +27 / +50 ms (2-slot A/B, both arms) over no-heavy windows, and it is the SAME with no judge lowering
    at all (2-slot A/B: 0 queue lowerings in either arm) -> the user's "ping/jitter high during a
    speedtest" is the shared path queue the heavy flow fills, not the judge; SELFQ only removes the
    needless lowering. See ab-*/ab81.txt.
 F3 HS2_LB_SLOW_SKIP_COPY=1  slowStreams (force close of "trickling" streams on retiring / cut-drained
    links) reads the rate EWMA, which flowStats never updates for copyOnly subs -> every copy sub looks
    trickling; the byte-snapshot guard is a no-op for the first candidate. lab2: c cut-drained 164 s,
    +60 s (cutDrainForce) the edge logged "1 trickling (not flowing): 1 on cut-path links retiring 1m+"
    and the call ended at 226 s with "write: broken pipe" (s1-lab2/ir-calldeath.log, result.json).
    Fix skips copyOnly streams (as lightStreams/evac already does). Test TestSlowSkipCopy (off: the
    flowing copy is closed; on: kept, trickling primary still closed). Not A/B'd (call placement random).
