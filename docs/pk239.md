## Design (as implemented)
- `HS2_QUEUE_CTL_SHAPER=mqchild`. At the first start, while parked, under the tree lock (`mqReady`):
  kernel >= 5.18 (uname), root qdisc is `mq`, >= 2 TX queues (sysfs; in a test netns without sysfs: the mq's highest child),
  clsact added once (refuses if an `ingress` qdisc is there), probe filter `skbedit queue_mapping N-1 priority 1fe1:1`
  (prio 65000, deleted), then the htb 1fe1: tree (default 1fe1:1 40 Gbit + fq_codel, same as root mode) grafted once on the
  LAST mq child; an existing tree there is reused (no graft) and gone processes' classes/filters are cleaned up.
  Any failure -> log + root mode (rel69c). Kharej (1 queue, fq_codel root) falls back, as the ABAB log shows.
- **Finding: the kernel's default mq has handle 0, and a handle-0 qdisc cannot be a parent** (lab1 eth0, kernel 6.8:
  `tc qdisc replace dev eth0 parent :14 …` and `parent 0:14` both -> "Failed to find specified qdisc"). So on a default
  root (prod Iran: `qdisc mq 0: root`), mqReady re-adds the same mq with handle `1fe0:` once (children =
  net.core.default_qdisc, exactly what the kernel creates) and logs it. This is ONE root graft at the first-ever start
  (parked); every later start finds `mq 1fe0:` + the child tree and grafts nothing. Verified by hand on lab1 eth0
  (re-handle + graft on 1fe0:14 OK, then restored with `qdisc del root`). Without it mqchild could never engage on prod.
- No filters while parked. Under a cap: clsact egress u32 per link (dst+dport) -> `action skbedit queue_mapping N-1 priority
  1fe1:M` (no mirred). Same hl234 two-generation swap, same drain-before-unsteer park as pk237 (`steers()` = ifb||mqc).
- Removal keeps the child tree (default class only) and clsact: taking either off is a graft; a restart reuses them.
  Two processes share the child tree (own minor + own filter prios).
